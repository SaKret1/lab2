
# Лабораторная работа №2
## Разработка и исследование уязвимого веб-приложения

### 1. Описание проекта

Данный проект представляет собой учебное веб-приложение, разработанное на языке Python с использованием Flask и SQLite.

Цель лабораторной работы — изучить распространённые уязвимости веб-приложений, продемонстрировать способы их эксплуатации, а также рассмотреть методы устранения обнаруженных проблем.

Приложение содержит систему авторизации и страницу поиска пользователей. В первоначальной версии намеренно реализованы две уязвимости из OWASP Top 10:

- **SQL Injection (SQL-инъекция)** — внедрение SQL-кода через пользовательский ввод.
- **XSS (Cross-Site Scripting)** — внедрение и выполнение JavaScript-кода в браузере.

Все испытания проводятся на локальном веб-сервере.

### 2. Используемые технологии

- Python — основной язык программирования.
- Flask — веб-фреймворк для создания приложения.
- SQLite — система управления базой данных.
- HTML — создание пользовательского интерфейса.
- Requests — отправка HTTP-запросов из Python-скриптов.
- Git — контроль версий проекта.

### 4. Запуск приложения

Для запуска проекта необходимо выполнить следующие действия.

**Шаг 1.** Установить зависимости:

```bash
pip install -r requirements.txt
```

**Шаг 2.** Запустить приложение:

```bash
python app.py
```

**Шаг 3.** Открыть веб-приложение в браузере:

http://127.0.0.1:5000

Для проверки авторизации предусмотрены следующие тестовые учётные записи:

| Логин | Пароль |
|---|---|
| admin | admin123 |
| user | user123 |
| student | student123 |

### 5. Реализованные уязвимости

#### 5.1. SQL Injection

Уязвимость реализована в функции авторизации файла `app.py`.

Причина возникновения — использование форматирования строк для формирования SQL-запроса. Пользовательский ввод напрямую включается в запрос к базе данных.

В результате злоумышленник может изменить логику SQL-запроса и обойти проверку логина и пароля.

Для демонстрации используется скрипт:

`exploits/sql_injection.py`

Скрипт отправляет специально сформированный HTTP-запрос и проверяет возможность обхода авторизации.

#### 5.2. XSS (Cross-Site Scripting)

Уязвимость реализована на странице поиска пользователей `templates/search.html`.

Причина возникновения — использование фильтра `safe`, отключающего автоматическое экранирование пользовательского ввода.

В результате внедрённый JavaScript может выполниться в браузере пользователя.

Для демонстрации используется скрипт:

`exploits/xss_test.py`

Он отправляет тестовую строку и проверяет, попал ли внедрённый код в HTML-ответ. Дополнительно выполнение JavaScript проверяется непосредственно в браузере.

### 6. Устранение уязвимостей

После демонстрации эксплуатации были подготовлены исправления.

**SQL Injection:**

Небезопасное формирование SQL-запроса заменено параметризованным запросом с использованием плейсхолдеров `?`.

Это позволяет отделить SQL-команды от пользовательских данных.

Файл исправления:

`patches/sql_injection_fix.diff`

**XSS:**

Удалён фильтр `safe`, отключавший автоматическое экранирование HTML.

Теперь пользовательский ввод отображается как обычный текст, а не интерпретируется браузером как HTML или JavaScript.

Файл исправления:

`patches/xss_fix.diff`

### 7. Проверка исправлений

После внесения изменений повторно запускаются Python-скрипты эксплуатации.

Ожидаемые результаты:

- SQL Injection больше не позволяет обойти авторизацию.
- XSS больше не приводит к выполнению внедрённого JavaScript.
- Обычная авторизация и поиск пользователей продолжают работать.

Таким образом, проверяется эффективность внесённых исправлений.
